# 1.0.2 光环槽读取修复

日期：2026-10-11。用户日志：1.0.1-beta.1，`equipment:74 → onLeave:220` 连续三次抛出 `Invalid aura slot field`，控制器随后 stopped。

## 原因与边界

已确认直接缺陷：定时显示刷新把光环槽不可用当成未处理异常，控制器收到 Frida error 后退出。原始 `dictionary_playersspells.json` 中前三光环槽初值为字符串，四、五槽未预置。旧实现假设五槽始终存在且为数值，不符合初始化生命周期。

用户发生错误时具体字段与类型未被旧版记录；不能断言全部来自转场或全部来自新存档。本机只读实机采样五槽均为数字 0。此次修复保证槽位不可用不会导致显示刷新杀死 Mod，新增诊断区分缺失、字符串、异常类型和值。不将不明值转换成 0，不写入未确认的槽位。

## 验收标准

| 项目 | 标准 | 结果 |
|---|---|---|
| 五槽读取 | 数字槽正常；逐槽覆盖缺失、空字符串、非空字符串、未知类型及非法 ID | Node 使用生产函数的边界测试通过 |
| 刷新生命周期 | 不可用时保持运行、明确显示状态；恢复后重新显示；同一错误不逐帧刷日志 | 自动测试通过 |
| 错误边界 | 字典损坏等其他错误仍明确失败；不无条件吞错 | 自动测试通过 |
| 装备写入 | 保留已有数值类型检查；不可用槽位不会被伪造为数值 | 源码检查；真实异常状态写入未执行 |
| 实机读取 | 当前游戏只读采样、修复函数在 Frida 中正常执行 | 通过：五槽均为数字 0；真实 VM 中 ready=true、模拟缺失第四槽 unavailable=false、恢复 recovered=true；模拟只改变 JS 字典副本 |
